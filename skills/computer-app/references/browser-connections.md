# Chrome and Edge special connections on a Mac

On a Mac, use the owner-installed **RemoPilot Browser** extension for Chrome tasks. Edge uses the owner's separately configured `remopilot-browser-edge`. New setup of the old Chrome connector is retired. An existing old configuration remains until explicitly disabled; recover any active or uncertain operation through its original connection and ID. Configuration or tool discovery does not prove browser access.

The Chrome extension registers `remopilot-chrome-extension` through the installed Mac app's native host. Ordinary extension operations control tabs in its Chrome profile without `chrome://inspect` remote debugging; heap-snapshot and Lighthouse use a separate debugging connection. For an existing browser the owner must enable and approve that connection; the source temporary-browser mode uses its own launched profile. The extension popup enables or pauses operations; already running operations finish. macOS may require the owner to permit the app to register the Chrome native host. Discover its exact catalog independently: its page and element IDs, available tools, output and screenshot behavior differ from Chrome DevTools MCP. After opening or navigating a page, use its `wait_page` tool before inspecting the loaded page. Opening a page activates its tab unless `background` is set; clicking or keyboard input brings the target browser window and tab to the front. Verify the effect with a fresh observation. Browser-internal pages and extension pages are restricted. Use one `browser:chrome:extension` resource for conflicting operations; a lost operation result remains uncertain and must not be replayed. The extension's configured state or catalog does not prove an actual browser operation works.

The source extension and adapter add `debugger_session_status` for the original page ID. It reports only in-memory extension evidence; an extension restart loses it, and a matching updated extension is required. Its `debuggerResources` identifies observations, active traces, retained browser trace streams and recordings that depend on that page's session. On pause or native-host disconnection, the source keeps those sessions attached so their resources can continue; observations may continue collecting events, and active recordings keep their scheduled maximum-duration stop. Reconnect or resume, then explicitly stop and release those resources. A closed tab, Chrome DevTools, extension restart or unexpected termination can still end the session or lose memory. If an attempted debugger detach fails without confirmation, the source implementation retains the session as `unknown`, blocks reattachment and page mutations, and does not assume the browser released its debugger. Keep the original call and session ID; a later detach event or confirmed tab closure can provide local detach evidence. A status that is absent or `not_tracked` is not proof that the original operation completed. An isolated test covered concurrent attachment with an injected initialization delay and observation/active-trace retention after an injected native-port disconnect. It injected the unknown-detach state; natural detach failure, recording retention and late trace events remain unverified.

The source adapter includes a temporary Chrome for Testing mode. With the ordinary extension connected, `isolated_browser_start` accepts a fresh `instanceId` and prepares a separate profile and extension bridge. A Google-signed app can be discovered automatically. Some testing archives do not have a verifiable signed app envelope: for an owner-trusted app, provide its exact executable path and `chromeExecutableSha256`. That pin checks the executable file only; it does not establish the integrity of the entire app or its origin. Check the same ID with `isolated_browser_status`, then use `isolated_browser_select` in the same MCP session once the instance is running and connected. Subsequent page IDs and actions belong to that selected instance; omit the ID to select the ordinary extension again. To inspect the original local diagnostic or trace-transfer records after an interruption, select the ID with `offline=true`; a cleaned instance is automatically offline, and browser actions are rejected there. The temporary browser uses its own local debugging port and does not inherit the normal profile's login. Stop observations, release retained traces and recordings, and finish diagnostics before `isolated_browser_stop` with the original ID. The supervisor removes the temporary profile and extension copy after confirmed browser exit only when its host, call journal and diagnostics permit it; the private instance directory and receipts remain. Uncertain calls or changed identities preserve the profile and evidence. Recover an uncertain start or stop by its original request and instance ID, never replay it. Use a consistent instance-specific coordination resource and do not expose its debugging endpoint. This feature has not been installed or accepted.

The extension also exposes `select_page` to focus a tab, `wait_for` to wait for text in the main document, `hover` on a fresh snapshot element, `type_text` to insert text into the focused element, and `fill_form` to fill text fields in sequence. Read their exact schemas: they do not duplicate every upstream option. A confirmed partial `fill_form` failure reports how many fields completed. Inspect the page before continuing; if the original result is uncertain, recover it instead of replaying the batch.

In source, `take_snapshot` can include bounded available accessibility properties with `verbose=true` or write its tree to a new workspace `filePath`; inspect `omitted`, since neither mode is a complete tree guarantee. `includeSnapshot=true` on supported input actions appends a fresh snapshot after a confirmed successful action. A separate snapshot failure does not undo that action; use its result rather than replaying it. `drag` accepts either `fromUid`/`toUid` or `from_uid`/`to_uid`; `upload_file` accepts either `files` or `filePaths`, with the same workspace checks. These source paths are not yet accepted on an installed client.

The source `wait_for` also accepts the upstream `timeout` spelling and `visible=false` to search hidden DOM text; its default still searches visible main-document text and it does not search child frames or accessible names. `evaluate_script` accepts the upstream `format=script|function` spelling for inline `function` or workspace `sourcePath`; script format does not accept element arguments. These options do not make the upstream and extension behaviors identical.

The source `select_page` accepts `bringToFront=false` to check an allowed tab without activating it. When omitted, it retains the extension's existing behavior of activating the tab and focusing the window. Every later page operation still requires its own `pageId`; this is not an upstream-style implicit page selection. An isolated test checked the returned focus and page-ID flags; installed-client behavior remains unverified.

The source `emulate` accepts upstream names `networkConditions`, `cpuThrottlingRate` and `prefersReducedMotion`, along with viewport and geolocation strings. Empty viewport or geolocation strings clear that individual override. Omitted non-media settings remain in effect, whereas supplying any media option replaces all media overrides; provide every media option to retain together. These semantics and network-profile values can differ from the upstream connector. The optional `extraHttpHeaders` takes a JSON string object, or an empty string to clear it. Never pass credentials: tool inputs may be retained, common credential header names are rejected, and the headers can reach any origin requested by the page. Settings are tracked only during the current debugger attachment. Stopping observation briefly disables the Chrome Network domain before reapplying this session's tracked network overrides, so requests during that interval may differ. An isolated test covered a viewport string and restoring and clearing a noncredential header; the remaining new input forms and network emulation restoration remain unverified.

For network or console debugging, call `browser_observe` with `action=start` before the relevant activity. Supply a fresh random UUID as `captureId` and retain it with the original task so status can be checked if the start result is uncertain. List concise, filtered and paginated results with `list_network_requests` or `list_console_messages`; pass the same captureId and advance `afterId` from `nextAfterId`. Fetch one item only when needed with `get_network_request` or `get_console_message`. Headers and request/response bodies require explicit flags, may contain sensitive data and are bounded. Stop observation with the same captureId when finished. Observation is tab-local and memory-only, holds at most 300 requests and 300 messages, and may not include out-of-process child frames. Current source retains the original debugger on pause or disconnection, so observation can keep collecting; other interruption or extension restart can lose its records. Never present missing older events as proof they did not occur.

With the updated source extension, if the original debugger's detach is unknown or confirmed, the same list and get tools can read the observation's already buffered records without attaching a new debugger. Their `incomplete` and `observationPhase` fields describe the interruption; requesting a network body cannot fetch it in this state. Status and retained records are available by original page and capture IDs even after a tab closes, but remain memory-only. A confirmed detached observation remains until `discard_browser_observation` explicitly discards its buffer without a browser command; it also prevents temporary-profile cleanup until then. Unknown state cannot be discarded this way and does not prove the original operation completed. An isolated test injected unknown detach, then closed the real test tab and read and discarded the retained observation by its original ID. These paths require a matching updated extension; natural detach failures and extension restarts remain unverified.

The source catalog also accepts `pageSize`/`pageIdx` for bounded indexed pages, `reqid` and `msgid` for observed item IDs, and `types` and `includeStackTraces` for console lists. Use either indexed paging or `afterId`/`limit`; indexed pages can shift as events arrive or older entries are evicted. Network resource-type filters ignore case. IDs belong to this observation, not the DevTools panel, and the buffer is not upstream's per-navigation history or service-worker log. These new forms are not yet verified in a built client.

`set_logpoints` accepts an exact HTTP(S) generated-script URL and a 1-based line and optional column, followed by the expression. It compiles every requested condition without running it before replacing existing logpoints. Exact duplicate locations use the last expression. The returned `boundAtCreation` and bounded `locations` describe only the instant of creation; an unresolved URL can bind after a matching script loads. They do not prove that the expression has run. Check console output separately, and recover an uncertain original call instead of modifying or replaying it; another change is rejected while the same debugging session's outcome is uncertain. Source-map source paths and original variable names are not resolved.

Manual performance tracing may reload with `reload=true` and optionally `ignoreCache=true`; `ignoreCache` requires reload. `detail=devtools` requires `retainRaw=true` and requests additional DevTools timeline, navigation and JavaScript sampling categories. `includeScreenshots=true` additionally requests page screenshot events and requires the DevTools detail profile; screenshots are off by default and may contain sensitive content. These options increase overhead and can exceed the selected storage limit. Requested categories do not establish trace completeness or provide full insights. Reusing an active `captureId` with different tracing options is rejected. Recover uncertain calls by their original call ID rather than restarting.

The source version additionally offers `storage=stream` with `retainRaw=true`: Chrome provides an IO stream that can be saved up to 512 MiB, without an immediate event summary. After stopping, save to a new workspace `.trace.json`. The transfer uses a private journal, verifies the original file and stream instance, and caches only the latest browser chunk. Resume an interrupted save with the same `pageId`, `captureId` and file path; never replay an unknown browser read. `performance_trace_transfer_status` checks local file evidence even if Chrome disconnects but cannot prove browser cleanup or complete capture. `discard_performance_trace` closes an available stream when explicitly requested. The stream JSON does not embed the browser's data-loss flag; retain the stop/save result or local transfer record. Recovery from process interruption is designed for, but power-loss recovery is not guaranteed. An isolated browser test saved and parsed a short trace and resumed after an artificially delayed response to an already completed chunk read. Actual process interruption and size limits remain unverified.

Tab-scoped extension traces can omit browser-process metadata needed to form DevTools insight sets. Source adds `performance_capture_isolated_trace` only for a selected temporary browser: it uses that instance's own trusted debugging connection and saves a new workspace `.trace.json` up to 512 MiB. Its browser-process data may include other pages of the same isolated profile; only use it within the user's authorized scope. `reload=true` reloads the selected page during recording and can change site data; `ignoreCache` requires reload. Keep the original `pageId`, `captureId`, file path and call ID, and inspect `performance_isolated_trace_status` if necessary. A reported data-loss flag or verified file digest does not establish completeness. It shares a durable admission barrier with heap snapshots and Lighthouse; preserve an uncertain call and do not replay it. An isolated Chrome for Testing 158 test exercised capture and the `DocumentLatency` insight; interruption and installed-client behavior remain unverified.

`performance_analyze_insight` is an offline DevTools Trace Engine integration for a workspace `.trace.json` of at most 512 MiB. Call with `filePath` to obtain a summary and available insight set IDs and names; specify both `insightSetId` and `insightName` to inspect one result. Check `insightSetsTruncated` and each set's `insightNamesTruncated` for bounded lists. Each call analyzes the file anew in a separate process, one at a time per machine connection, and returns its digest. Large files can still exhaust memory or fail. It does not fetch source maps or CrUX, and file metadata including a reported data-loss flag is not independently verified. Missing events, limited categories or absent metadata can make insights unavailable or incomplete. A compiled gateway analyzed an actual short trace in an isolated test; individual insight results and the installed client remain unverified.

The source `take_heapsnapshot` tool uses a separate local Chrome DevTools session because extension `chrome.debugger` does not allow the HeapProfiler domain. For an existing browser, the owner must enable remote debugging and personally approve Chrome's prompt; never enable or approve it on their behalf. A selected temporary instance uses its own profile instead. The extension supplies the exact tab target ID and the debugging connection must report that same HTTP(S) page. Supply a fresh `captureId`, workspace `.heapsnapshot` path, and optionally an absolute `profileDirectory` for the existing Chrome user-data root containing `DevToolsActivePort`. The file can contain sensitive memory and is limited to 512 MiB. A durable record blocks new heap captures and Lighthouse audits if the original capture is uncertain. Recover the original MCP request and use `heap_snapshot_status` with its original page, capture and file path; do not repeat an uncertain capture. A completed status verifies the saved file digest, but not JSON validity. An isolated test parsed an actual snapshot and checked its digest; existing-browser approval, interruption and installed-client use remain unverified.

The source `lighthouse_audit` likewise uses the owner's separately approved Chrome remote-debugging connection for an existing browser, or the selected temporary instance's own profile, and verifies the precise extension target. It uses the pinned upstream Lighthouse engine for accessibility, SEO, best practices and agentic browsing; performance remains a separate trace. Provide a new `captureId` and an existing workspace `outputDirPath` for new JSON and HTML reports. The response includes scores and bounded failed-audit and node excerpts; check `failedAuditsTruncated` and `nodesTruncated`, and use the reports for full details. `mode=navigation` reloads the page, whereas `snapshot` inspects its current state; `device` chooses desktop or mobile. Lighthouse's own storage reset is disabled, but page navigation and scripts may still modify site data. Reports and excerpts may contain sensitive page content. Retain the original call and inspect `lighthouse_audit_status` by original page, capture and output directory if needed; missing or unknown status does not prove completion. Heap capture and Lighthouse share an admission barrier, and a still-live uncertain audit keeps the original request pending rather than disconnecting it. An isolated test verified navigation reports and their digests; snapshot mode, interrupted audits and installed capability remain unverified.

Check the audit or status result's `emulation` field. After a confirmed audit, the source attempts to restore only the overrides tracked since the current extension debugging session attached. A changed session or concurrent extension emulation revision skips restoration; `otherOverridesVerified=false` means settings from other clients are not verified. Restoration may briefly resize the page. Coordinate other page operations during an audit and do not assume an absent or unsuccessful result means the original settings were restored.

The source version of `evaluate_script` accepts exactly one inline `expression`, inline `function`, or workspace regular-file `sourcePath`. Files default to function source; set `sourceFormat=expression` for expressions. Functions may receive current snapshot element IDs in `args`, subject to compatible page execution contexts. An optional `filePath` writes bounded JSON to a new workspace file and reports its digest. The destination is created before dispatch and can remain empty or partial on failure or uncertainty; the script may have changed the page, so recover the original call instead of replaying it. An isolated browser test exercised a file script and saved result; this implementation does not provide every option of the older connector.

In a newly completed trace, `dataLoss=null` means the browser's data-loss flag was unavailable or malformed; do not treat it as `false`.

Experimental page-only recording uses `screencast_start` with a fresh captureId, then `screencast_stop`, `save_screencast` to a new workspace MP4, and `discard_screencast` with that same ID. It has no audio, requests automatic stop after 60 seconds and saves at most 64 MiB and 10000 chunks. The extension reads the browser stream sequentially and caches confirmed chunks in memory; a failed transfer can be retried to a new file, but an uncertain browser-stream read remains unknown and is never blindly repeated. If a limit is exceeded, discard the recording. `screencast_status` reads extension-local state; complete means Chrome returned a stream after stopping, not that the video is complete or playable. Recover uncertain operations through their original call ID and never treat unknown or not-found as completion. The source keeps its debugger session on pause or disconnection, but an external detach, restart or unexpected termination can still lose the stream. Output may contain sensitive content; a failed save can leave a partial file. Browser support and end-to-end behavior require verification on the actual installation.

`performance_trace` records a short actual Chrome trace and returns bounded event aggregates and slow tasks, not a raw trace or full DevTools performance insights; manual tracing has a separate optional raw-event workflow below. `drag` requires both snapshot elements to be simultaneously visible and moves the window to the front. `take_screenshot` can return a bounded inline image or create a new format-matching image file in the bound workspace and return its digest. A failed write may leave a partial file; use a new path to retry. `upload_file` selects authorized regular files inside the selected project binding; selecting a file can itself trigger upload. Inspect and follow the actual schema, use only files the user authorized, and verify effects separately. These tools do not provide all Chrome DevTools MCP capabilities. Treat trace and emulation changes as browser operations, and preserve original IDs on uncertain results.

The extension also supports history navigation, modifier key combinations, JavaScript dialog handling, computed and matching CSS, window resizing, and exact-URL script logpoints. Attach before the page opens a dialog. `performance_start_trace` and `performance_stop_trace` take the same caller-supplied `captureId` and produce bounded aggregates. With `retainRaw=true` and the default `storage=memory`, the extension may retain up to 32 MiB of raw trace events: check `rawTraceAvailable`, `rawTraceOverflow`, and `dataLoss`, then save with `save_performance_trace` to a new workspace `.trace.json` and release it with `discard_performance_trace`. Only one raw trace can be retained; it is lost on extension restart, may contain sensitive data, and a failed save can leave a partial file. Current source versions of both extension and adapter keep a private transfer record for each target path: once the original call has ended, an interrupted memory save can continue with the same page, capture, and path if the original retained trace is still available and the file and its confirmed prefix match. A completed record is not overwritten; use `performance_trace_transfer_status` to verify it. Saving a separate copy requires another new path. Older extensions lack the trace-instance identity, report `resumable=false` on a successful save, and retain their new-path-only retry behavior. A missing record, changed file, extension restart, or discarded trace does not prove the original operation completed. Recover an uncertain original call by its original call ID; `performance_trace_status` can also read extension state for the original page and capture IDs, including a completion event received after a stop timeout. It does not start or stop anything; unknown, detached, or not-found states do not prove completion. Only the latest completed manual summary is held and a new manual start replaces it; extension restart loses it. The categories are limited, retention adds overhead, and this is not full DevTools performance insight analysis. Never start or stop it again when the original result is uncertain. Network, geolocation, user-agent and media emulation are available as explicit options; media options include color scheme, reduced motion, forced colors and contrast. Changing any media feature replaces all media-feature overrides, so specify all desired features together. Clear overrides after use. Screenshot output is bounded and can include the viewport, a snapshot element, or a full page.

1. Retain the selected machine binding and RemoPilot session. Check its `localMcpCatalog` or `mcp_servers`; do not use a connector configured on a different computer. `mcp_tools` connects to the named MCP and returns its actual tool schemas and fingerprints; this alone does not connect the browser. When its current input schema supports `names`, request just the exact known tools needed, such as `["list_pages", "browser_observe"]`; omit it to discover the full catalog. A large catalog can return `delivery=artifact` instead of inline `tools`: call `read_artifact` on the same binding with the returned `source.artifactId`, use `nextByteOffset` while `truncated` is true, and reconstruct the original JSON before selecting its `serverFingerprint`, tool `inputSchema` and `inputSchemaSha256`. Do not mistake the artifact summary for the catalog. Call the current page-listing tool according to that schema to establish and verify the actual browser session.
2. Edge's existing-browser mode, and Chrome's heap-snapshot and Lighthouse diagnostics on an existing browser, require the owner to enable remote debugging in the browser's inspect page and approve any prompt. Ordinary Chrome extension operations do not. The Mac client's authorization guidance links to the browser and macOS privacy settings. An `EPERM` reading `DevToolsActivePort` can mean the actual background app lacks browser-data access; the owner can check **Privacy & Security → Files & Folders** and retry only after the original call has a terminal outcome. A 403 can require browser approval; do not infer approval from the error alone. Browser versions and policy determine availability. Use only the user's requested scope and never enable debugging or accept the prompt yourself.
3. Edge's separate-window mode launches a temporary profile when first used. The Chrome extension's distinct temporary-browser mode is described above. Neither inherits the user's normal login. Keep all calls for one interaction on its original session, and use the same `browser:edge:existing` resource for conflicting Edge existing-profile actions.
4. Use `mcp_call` with the exact server and input-schema fingerprints returned for the same session. Calls use the cached schemas; on `MCP_CATALOG_STALE`, reconnect or a known tool change, refresh with a new `mcp_tools` request and fresh keys. Servers that send no tools-list change notification can change without automatic detection. Observe the actual page and current snapshot before input, then verify the effect. External MCP responses, including images and network/page data, can contain private information. Current `mcp_call` wraps the upstream result and limits it to 1 MiB; do not assume a nested image is directly viewable, and do not claim a screenshot was inspected when it was not. If an allowed screenshot file and the matching `read_artifact` path are available, inspect the actual image; otherwise report this limitation and use verified page snapshots where sufficient.
5. If a call or connection is uncertain, recover the original request/call and inspect the existing page; do not repeat a click or navigation. Disabling or changing the configuration blocks new calls and asks the updated gateway to retire idle browser MCP sessions. An already active or uncertain call retains its original connection and evidence; do not force-close the user's browser. Gateways running an older version may retain idle sessions until they close, so the switch alone is not proof that every old session has ended. After re-enabling or a gateway restart, obtain fresh schemas and fingerprints for the original task session. Use a new idempotency key for this new discovery; a recovered old discovery receipt can contain a fingerprint from the previous gateway. Never replay an uncertain browser action.

Chrome DevTools MCP exposes its own tools and permissions through the existing external-MCP operations. It is not a new built-in gateway tool, a filesystem sandbox, or proof that Edge or a particular browser version has passed acceptance on this machine.
