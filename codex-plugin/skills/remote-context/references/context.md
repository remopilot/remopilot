# Checkpoints and execution history

context_checkpoint stores an immutable caller-written plan/progress snapshot. Follow [planning.md](../../remote-workspace/references/planning.md) for the initial plan, explicit primary binding and verified storage. Save visible decisions and concise per-action references; do not claim automatic capture of all observations or host chat. sourceHandoffId links an earlier snapshot without inheriting permission. runs references pin available request events at save time; later progress does not alter the snapshot.

Scoped checkpoints require a structured workspaceMap and primaryBindingId. The cloud requires at least one binding and stores content on that explicit primary machine; storage.kind=machine/cloudIndexOnly=true means the cloud is index-only and that machine must be online. Local relay may accept an unscoped empty binding list and report storage.kind=sqlite. Report actual storage fields, not guessed paths or tables. Local summaries are limited to 64 KiB and cloud summaries to 256 KiB; link full evidence instead of copying it.

context_restore returns a compact state and original history references. hasNewEvents means there are events after the snapshot, not that they have been read or acted on. Read workspace_events from the prior sequence through a fixed bound, following nextSequence until the relevant pages are complete. Explain inaccessible, expired or unsupported evidence. Inspect constraints, unresolved issues, latest user input and original execution state before continuing; restoration never cancels, redispatches or proves completion.

Use workspace_history(source="agent") with an explicit original binding for complete redacted execution receipts. Lists use after and a fixed throughSequence (passed as through on later pages). Details select exactly one of recordId, executionCallId or requestId; callId is not an alias. On HISTORY_AMBIGUOUS, choose an actual returned recordId. Continue detail fragments with recordId and nextOffset on the same binding/source, concatenate JSON fragments before parsing, and preserve incomplete evidence. A new authorized binding to the same project can inspect its retained history; a changed path is not automatically that project.

Cloud source="relay" is a routing index with after/through/limit, not the full arguments/results journal. Use source="agent" for details. Local relay sources retain the functions actually advertised in their catalog. Missing evidence on one side never justifies replay on the other.

Keep the returned taskUrl as the authenticated latest-plan link and the handoffId as the snapshot ID. The task page's call indices show relay observations, not verified execution success. Summaries reduce material needed for continuation; they do not delete the host's original chat or make an offline storage machine available.
