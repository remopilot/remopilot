# Develop in the selected project

Use the [core calling contract](../cloud-connection/references/calls.md) once per task and target version. Reuse the explicit machine/project binding and session; bind a known authorized project directly, or use workspace_open when the target is unclear. When the host determines a durable plan is needed, use the [planning contract](../cloud-connection/references/planning.md) and verify its storage.

1. Read applicable AGENTS.md/AGENTS.override.md, and, when a task record is appropriate, open the authorized project journal and read its lessons under [project-journal.md](../cloud-connection/references/project-journal.md). Inspect relevant files and Git differences. Preserve unrelated changes; pause only files with unsafe conflicts.
2. Use read_files for known text files. When command access is enabled, use bounded platform commands such as stat to inspect metadata and authorized shell commands for file moves; check the source and destination before moving and do not assume overwrite protection. When command execution is enabled, inspect project configuration and Git status, then use bounded `rg` through run_command for discovery. Restrict directories, file types and patterns before running; exclude generated trees, credentials and sensitive paths. Do not add `--hidden`, `--no-ignore` or follow links broadly. Limit long lines and total output, check exit/truncation and search smaller scopes when evidence is incomplete. Search output and Git diffs may contain secrets; never print or retain sensitive values. Command access is a separate machine permission and is not implied by project or desktop access. If disabled, the removed repository/search operations are unavailable; do not bypass the permission. See [paths-and-budgets.md](../cloud-connection/references/paths-and-budgets.md).
3. Use project-relative paths with pathMode="workspace", or remote absolute paths with pathMode="absolute". Omit repoPath/cwd to use the bound root. For run_command subdirectories, put workDir on that operation’s own call. Other project tools require their own exact project binding.
4. Edit with exact batch matches or write_file overwrite/content guards. write_file checks expectedSha256 against the initially read content and uses a shared path lock and atomic replacement; other writers that ignore the lock can change the file afterward and have their changes overwritten. Coordinate shared writes and track external changes. On MATCH_COUNT, HASH_MISMATCH or HEAD_MOVED, reread current state and rebuild the smallest patch; do not weaken guards or replay a failed mutation unchanged.
5. Follow the user's and project's verification timing. Select checks from the actual project configuration; record which required checks passed, failed, were skipped or could not run. Never infer coverage from a successful shell exit alone. Use separate run_command calls or explicit fail-fast shell chaining for dependent checks; do not change build inputs while a build runs.

Independent work may run concurrently after checking shared resources. For an authorized Git commit, inspect HEAD, branch, working tree, the existing real index, hooks, target paths and hashes first. Declare `coordination={scope:"resources",resources:["git"]}` for the entire dependent staging/check/commit sequence on the original project binding; the key resolves to the verified common repository across worktrees. This coordination is cooperative and cannot exclude external Git processes. Use a new private `GIT_INDEX_FILE` initialized from the recorded HEAD, stage only reviewed task changes or an exact reviewed patch, and inspect its complete staged diff and file hashes before committing. Refuse conflicts, unexpected files, sensitive/generated content or changed inputs. Recheck HEAD immediately before commit and verify the resulting parent, tree and file list afterwards; an external concurrent Git command may still race the check. Preserve the real index and all unrelated staged changes; do not reset it. If the original index needs reconciliation after a successful commit, update only verified matching entries after checking it has not changed, otherwise leave it untouched and report its state. A failed or interrupted commit may already have advanced HEAD: recover the original run and inspect its actual parent/tree before considering any further action. Do not blindly rerun, push or change history. Inspect hooks and shared outputs before choosing other scopes. Inspection, commit, push, publication and installation each require their corresponding authorization.

Retain original execution and artifact references, inspect terminal state before depending on results, and report verification gaps plainly. Use [computer-mobile](../computer-mobile/SKILL.md) for iOS Simulator execution, [computer-app](../computer-app/SKILL.md) for installed app interaction, the [concurrency reference](../computer-tasks/references/concurrency.md) for independent branches, or [recovery.md](../cloud-connection/references/recovery.md) for interrupted calls. Source-only work stays here.
