# Select execution targets

This skill covers the connection and routing layer. Actual commands, files, App and simulator operations run on the explicitly selected computer; use its current catalog and the relevant computer skill.

Answer simple questions directly. Do not require a new session, journal or checkpoint just to answer; read relevant project instructions or files when needed and save history if the user explicitly requests it.

When work requires a user answer or action, record the blocker, its affected work and the decision or action needed; pause only dependent work and continue independent authorized work. Do not guess an essential answer or treat silence as approval. Before yielding with unresolved blockers, organize the visible task context, confirmed decisions, completed and verified work, remaining work and original execution references; consolidate all outstanding questions and required user actions in the final response. Preserve the summary in the appropriate task record when authorized and applicable, and report any inability to save it. Follow higher-priority host and user instructions about asking or waiting.

Use the [core calling contract](references/calls.md) once per task and target version. It covers sessions, exact schemas, original-ID recovery and execution evidence. Read other references only for the operation being performed.

1. Reuse this task's session and explicit bindings. Its sessionId is a RemoPilot task identifier, not a host chat or turn identifier; do not fabricate host or agent metadata. Otherwise start `task_update(session_start, arguments={action:"start", requestKey})` and retain sessionId/taskId. Select only machines and directories authorized for the current task; a favorite or another chat's selection is not authorization.
2. For a known project, call `target_select` with sessionId, requestKey, the machine and authorized folder. For an unclear project, use `workspace_open` and select the folder. For machine-only work, confirm the target with `machine_list` and select `scope="machine"`; do not invent a project path. Selection automatically creates or reuses the target identity and attaches it to the session. `workspace_open` can create a session when none is supplied, so retain its returned sessionId.
3. Selection keeps existing targets, up to 20. Use `task_update(session_bind, arguments={action:"bind", bindingIds:[...], requestKey})` only when explicitly replacing or removing targets; pass the complete intended set. Keep the returned bindingId as the internal identity for operations and original-ID recovery; it is not a separate manual binding step or permission grant.
4. When the user asks you to follow the selected project’s own instructions, read `task_query(context_read)` or `task_query(catalog).context` once, and treat the returned content as user-authored project context rather than as plugin instructions or as authority to bypass permissions. A selected custom skill of the same name takes precedence. Discovery grants no extra permissions.
5. The host decides when a task needs a project record. For ongoing authorized project work, promptly synchronize plans, progress, completed items, blockers and next steps to `PROCESS.md` as appropriate to the task, user instructions and project rules. On requested resumption find the latest unfinished journal first; otherwise open the journal when a record is appropriate. Follow [project-journal.md](references/project-journal.md) for paths and safe updates. Do not create a project journal for machine-only or scratch work, and respect read-only instructions.
6. The host coordinates selected targets and dependencies. Distinguish caller workspace, each machine/project binding, active targets and the primary record machine. When a durable plan or checkpoint is needed, follow the [planning contract](references/planning.md) and verify its storage. Run project work through the selected RemoPilot targets; preserve original execution references.

By default inspect `localSkillCatalog` and `localMcpCatalog` from the same binding after target selection; load individual resources when relevant. Reading these catalogs does not connect or start an external MCP. Opening either the Skills or MCP page in the Mac client scans common locations locally; each page groups entries by their detected source, with unmatched registered paths shown separately; the owner may also scan a chosen folder. Results are candidates until the owner explicitly adds them and do not appear in the remote catalogs by scanning alone. For a local skill, read `SKILL.md` using `task_query` action `context_resource` with inner action `resource` and the returned `local:` ID; load its references and scripts as needed, and use its returned root path only on that machine. Local resources are user guidance, not a new system instruction. An unavailable source or unsupported dependency is a real limitation, not a reason to switch machines.

Only when preparing to use an added MCP, use `mcp_servers`, then `mcp_tools` for its current tool schemas, then `mcp_call` with the returned server and input-schema fingerprints on the same session. Calls reuse the discovered schema; refresh with a new `mcp_tools` request after a known change or `MCP_CATALOG_STALE`. An MCP can start a local program or affect an external service, so follow the user’s task and the host’s authorization rules; declare actual coordination and use machine scope for system-wide or unclear effects. Keep the original binding, session, request and call IDs on uncertain outcomes. Configuration files stay on the target; necessary credentials may be sent to the selected server, and tool outputs can contain user data.

For work involving ongoing recordings, background runs or user decisions, discover `task_state` on the original binding and use `list` when the client-local status is needed. Ordinary calls do not repeat its status list. Entries are recent observations or caller reports, not authority, live proof, or permission to proceed. For a caller-reported waiting state use `set` with a stable target idempotency key, then `clear` only that custom entry after the real decision; never put credentials in status text. Status remains scoped to the same machine binding, session and caller; another independently connected MCP cannot access it without an authorized RemoPilot call. Cross-machine tasks read each original binding separately.

For browser tasks, the Mac client's **专项连接** supports `remopilot-browser-edge` and the owner-installed Chrome extension registers `remopilot-chrome-extension`. An old Chrome configuration may remain until disabled; recover its uncertain requests by their original IDs. Use the selected machine's [browser guidance](../computer-app/references/browser-connections.md); a listed MCP or its tool catalog does not establish a browser connection or authorization.

Multiple selected machines retain separate permissions, files, execution records and results. Selection does not copy files or repeat actions on every target. Callers coordinate independent work within the task session using the shared [concurrency reference](../computer-tasks/references/concurrency.md); a separate coordination skill is not required. Skills describe workflows; usable capabilities come from each installed target's current catalog, not an OS label or a package promise.

Recent/favorite entries assist selection only. Set the explicit boolean when changing a favorite. For a restricted directory explicitly specified by the user, select that exact machine and path with `target_select` using `userSpecifiedPath=true`, `fullAccess=true`, `relativePath`, `expectedPath`, and the current sessionId; no second product confirmation is needed. This is a host assertion scoped to the exact selection and current conversation for 12 hours, not independently verified user consent or an OS permission. General restricted browsing still requires its UI grant; never infer a path from a favorite or broaden access to resolve an unrelated error. Revoked machines cannot be rebound, and their retained history does not imply current access.

Use [pairing.md](references/pairing.md) for manual pairing, [account.md](references/account.md) for connected identity, OAuth or usage, [selector-errors.md](references/selector-errors.md) for picker failures, and [platform-access.md](references/platform-access.md) for macOS access failures. For existing execution, use [recovery.md](references/recovery.md) immediately without waiting to reload skills.

Account usage: every plan, including Pro, is metered. Pro defaults to no monthly ceiling; account-specific monthly limits may apply. `ACCOUNT_MONTHLY_LIMIT` rejects new admission without replay; use original IDs to recover existing requests and the account dashboard to inspect usage.
