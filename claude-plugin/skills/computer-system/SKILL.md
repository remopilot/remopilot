# Machine diagnostics and commands

Use the [core calling contract](../cloud-connection/references/calls.md) once per task and target version. Confirm the requested machine with `machine_list`; inspect online state, agentVersion, command permission and machineRoutingSupported. Offline metadata is historical evidence.

Reuse the explicit task binding, or create `target_select(scope="machine", machineId, sessionId, requestKey)` when no project is needed. A machine binding is routing, not a shell sandbox. It does not accept project paths, cwd, pathMode or workDir. Commands start in the machine's configured user work directory and run with its OS user's permissions. Do not substitute caller-local commands or bind an arbitrary project to bypass missing machine support.

Each tool and its selected action has a precise input schema; read it before composing arguments. Use gateway_inspect(action=profile) for capabilities and gateway_inspect(action=diagnose) for health; use gateway_inspect(action=usage) or gateway_inspect(action=calls) only for statistics or call anomalies, not task progress. Interpret the installed toolchain before choosing commands. See [diagnostics.md](references/diagnostics.md) when diagnosing a failure.

For changes, keep the target plan under the [planning contract](../cloud-connection/references/planning.md). Declare machine coordination for installation, service registration or machine-wide changes; declare shared resources for bounded conflicts. Starting a long command in detached mode changes observation, not its execution deadline. Retain original IDs and verify terminal state and effects before reporting completion.

Check desktopSessionAvailable only when GUI work is relevant. If absent, inspect desktop diagnostics; unknown is not unavailable, and enabled configuration is not proof of a usable screen. When unavailable, continue independent files/commands and report the requested GUI portion as blocked. Do not start display services or enable permissions automatically. Use [computer-app](../computer-app/SKILL.md) for apps, [computer-mobile](../computer-mobile/SKILL.md) for Simulator projects, and [computer-tasks](../computer-tasks/SKILL.md) for execution recovery.

A user-authorized update needs machine coordination. Download, installation, service activation and background access are distinct results; inspect their evidence separately. An old running generation can remain for its original tasks. Do not retire it, delete state or replay an execution to resolve a version difference. For a requested browser desktop connection, inspect the advertised capability and read [remote-desktop.md](../computer-app/references/remote-desktop.md).

Mac App lifecycle commands use only the recorded managed cloud connection: `remopilot app-control --action status|restart|quit|logout|enable-desktop|disable-desktop|enable-commands|disable-commands`. Status checks a fresh helper under the background identity, reports command and desktop capabilities separately from macOS grants, and does not prove existing App sessions have applied a grant. These mutations require explicit user authorization and machine coordination. Normal restart and capability changes require a nonce-bound idle intake pause; `restart --interrupt yes` is available after the owner confirms interruption. Enable-desktop writes `allowDesktop` only after the original PID exit is confirmed, then starts the same generation so missing TCC permissions can be requested; enable-commands does likewise and grants shell execution as the current OS user, with directory roots not acting as a sandbox. Disabling either capability follows the same idle stop and start checks; disabling desktop also disables whole-screen viewing and remote desktop. These are owner actions, never automatic permission grants. Explicit quit disables login startup and stops the selected managed agent even with active work; after a brief grace period it may force-stop the verified original PID. Work may be interrupted or continue in child processes; original requests and receipts remain for recovery without replay. Other connections and draining older generations are preserved. Closing the window hides it; a full App quit waits for the selected background stop to be confirmed and stays open if it cannot be confirmed. Inspect `status.quitOperation` and the saved operationId if the result is unconfirmed.

Explicit logout also stops the selected agent and revokes only its current machine credential on a supporting account service. Original requests and receipts remain; revocation does not release a device slot. Re-pairing the original account reuses that identity; switching to another account prepares a separate connection, and `remopilot account-activate --config PATH` installs and starts its service after pairing is confirmed. Activation requires machine coordination. An unavailable logout endpoint is detected before stopping the background; a later uncertain result must be checked against the saved operation and account state, never assumed successful. Prefer the local App lifecycle entry, since stopping an agent from its own remote job can interrupt its response. Never replay an uncertain request.
