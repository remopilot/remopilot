# iOS Simulator

- Read only relevant project information: applicable instructions, Git state, Flutter/pubspec or Xcode workspace, scheme, bundle ID, and available simulators. Prefer existing project configuration; device_run does not create missing platform projects.
- Bind the directory that actually contains ios/Runner.xcworkspace or the Xcode project. The parent bindingId remains the target for its original tasks; a child binding does not transfer them.
- device_run defaults to dryRun=true; a successful plan is not execution. The current agent defaults to instancePolicy=on_conflict: borrow the specified booted instance if free, or create and boot an independent simulator of the same type/runtime if occupied. Shut down and delete self-created instances only after every original stage run is confirmed ended; preserve the original simulator. Unknown closure retains the instance and its recovery record. new always creates an instance; existing strictly uses the specified instance. Explicitly boot an existing unbooted instance first; it is not taken over automatically. Use returned instance and actual deviceId, not the source UDID, as execution evidence.
- build/screenshot/log alone do not create, close, or exclusively reserve a device. Screenshot-only work observes the original specified device; do not mistake a blank new simulator for the original app.
- Include screenshot with build/install/launch in the same managed workflow when a final image is needed, avoiding capture of the source device after a self-created instance closes. The background workflow completes all selected stages continuously. Recover pending_call through its original callId rather than calling device_run again to create another instance.
- Runner results require MCP structuredContent and execution.version=1; bare results and legacy aliases are unsupported. Recover each stage with its fixed original runId. A terminal query receipt describes the query; the target must separately report the same runId and consistent status/unfinished/closureUnknown before the next stage or instance cleanup. Failed, unsupported or mismatched queries never authorize a replacement run.
- device_run waitMs is an initial observation window from 0 through 60,000 milliseconds. Owned workflows observe original runs with manage_run(action="wait", waitMs); expiry does not end a stage or change its ID. Resume skips a stage only after the original successful terminal run, exact commandFingerprint, workflow/attempt/target binding and artifact hash are verified. Artifact recovery may repeat a stage only after its original successful run was confirmed ended.
- Available stages are build/install/launch/screenshot/log. Flutter simulators currently support debug only. For a screenshot, select only screenshot without rebuilding or relaunching. Across staged calls retain the same workflowId and original stage evidence. For complete resume data, use a returned fullResult pointer when available. Only a local relay whose current input schema explicitly supports resultDetail accepts workspace_result(resultDetail="full"). Cloud workspace_result does not accept resultDetail; omit it and read the original output. Query the original call/run for missing data rather than inventing it.
- For dart-define, flavor, or unsupported build options, use the project's existing workflow through run_command(mode="detached") on the same binding. Read the actual schema and query the original runId; lack of output is no reason to restart a build.
- simctl screenshots contain only the simulator display, not the Mac desktop, but may still show the system or launch screen. Inspect the image. Screenshots include system regions such as the iOS status bar; do not claim strict app-pixel cropping.
- For remote screenshots, use the returned artifactId/download capability. A remote path is not a client-local path. Display a local absolute path only after confirming the execution machine is the current host and the file exists. Download into an explicit delivery directory before sending; an inaccessible path is not image delivery.
- Record device model, OS version, and mock/real backend mode. Do not claim unverified interactions or backend checks passed.

See [targeted observation](../../remote-app/references/targeted-observation.md) for image budgets, compressed copies, and artifact delivery. Device images are visual evidence only; device_run provides no screenshot-coordinate interaction. Do not apply app entity input parameters to device tools.
