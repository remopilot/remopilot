# Separate administrator browser desktop workflow

A target may advertise an opted-in browser desktop test for active OWNER/ADMIN users on their own paired macOS or Windows machines. Check the installed capability, usable screen and background OS permissions before offering its dashboard entry. On Windows the helper acts on the unlocked interactive desktop of the logged-in user: it cannot see or feed the lock screen or UAC prompts, and input does not reach windows running as administrator. Administrator status does not grant control of another account's machine, and App desktop permission alone does not enable this separate feature.

Use view mode first and enable control only within the user's request. This workflow acts on the user's real main display through direct WebRTC; it is not an isolated App Entity. Keep viewing, input authorization and verified disconnection separate. A timed-out or unconfirmed original session must be recovered rather than replaced, and a stale image is not a safe input target.

This is a browser workflow, not workspace_call screen streaming or global input. It does not bypass entity ownership, fresh snapshots or App tool permissions. Capability metadata, source implementation and a real connection are separate evidence. Configuration, service lifecycle and implementation details belong to the service's maintenance documentation.
