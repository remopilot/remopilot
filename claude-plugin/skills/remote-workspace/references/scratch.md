# Project scratch space

Use workspace_scratch(bindingId, requestKey) to create or reopen project-specific space for temporary files, downloads, and user-requested conversation summaries. It returns a separate binding and path; use that binding for subsequent reads, writes, execution, and task queries. Original source-project tasks retain their original binding. Space persists in the execution agent's managed directory with tmp/, downloads/, and conversations/. It does not automatically download, capture chat, save secrets, initialize Git, or clean files. Identify a project first if none exists; do not silently choose a default directory. Scratch space is excluded from recent/favorite locations; reopen it from the original project.

This scratch space lives on the selected execution machine. It is distinct from the caller workspace used for disposable drafts. Persist the actionable plan and progress on a selected execution machine using the shared durable planning contract; caller-local drafts may be cleared after interruption. Verification and computation in scratch must use its own binding and preserve original call and artifact references; copying a caller-local draft does not verify it on the target.

Local owner maintenance uses `remopilot scratch --state <current-work-directory>/.remopilot/agent --project <project-path> --action status|preview|cleanup`. Status and preview are read-only. Cleanup additionally requires `--confirm yes`, the current `config.json` at that exact agent directory, stopped services and generation processes, terminal executions and acknowledged delivery receipts, and no App controller blockers. It holds the installation's update lock and the Agent startup lock while moving eligible tmp/downloads files into recoverable `.trash`; it does not delete generation locks, infer closure from elapsed time, or expose a remote cleanup action.
